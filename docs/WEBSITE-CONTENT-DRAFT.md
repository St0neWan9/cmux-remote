## 叙事与编排

核心定位：**让远端的 Agent，成为随手可用的开发现场。**

阅读顺序：远端运行 → Mac 的两种接入方式 → 面向远距离的文本交互 → iPhone 会话体验 → 直连与自建中转 → 开源与独立 → 开始使用 → FAQ。

远端设备和正在运行的 Agent 是整页主角。Mac 与 iPhone 是接入同一个开发现场的不同入口。会话、Diff、权限确认作为使用过程展示，不再各自占据首页同等大小的功能卡片。

本稿里的「页面文案」可用于下一轮排版；「画面建议」和末尾的「编辑依据」仅供评审，不上首页。暖白背景、暖灰卡片、蓝色按钮和文字强调继续遵循根目录 DESIGN.md。

建议导航：**Mac 远程开发 / iPhone / 如何连接 / 开源 / GitHub**。

辅助标签：**开源 / 独立运行 / 可自建中转**

### 画面建议

首屏先表达「远端主机上的 cmux 与 Agent → 本地 Mac / iPhone」关系。远端节点明确标注“代码与 Agent 在这里运行”；本地 Mac 展示工作区与 TUI，iPhone 展示同一任务的结构化会话。不要只放一台 Mac 与一台 iPhone，造成“把本地聊天搬到手机”的理解。

## 03 · 远距离：突出 Agent 工作流的价值

### 页面文案

标题：**跨城、跨国，继续你的终端工作流。**

正文：无论远端设备在另一座城市、另一个国家，还是大洋另一边，查看 Agent 输出、继续输入、检查代码改动，依然是熟悉的开发流程。终端与会话直接呈现工作内容，让你专注远端任务，减少来回操纵整张桌面的步骤。

三个短标签：**终端输入 / 工作区切换 / 会话与代码改动**

### 画面建议

用“本地输入 → 远端 Agent 执行 → 输出与改动返回”的轻量示意讲清工作方式。地域可用文字标签，不制作伪造的 ping、延迟读数、速度对比或世界地图测速动画。

这部分承担远距离场景定位。后续若有同条件下的 SSH、镜像、远程桌面测试，可以补充真实体验与测量数据。

## 04 · iPhone：给手机自己的开发方式

### 页面文案

标题：**拿起 iPhone，像用 Codex 一样继续开发。**

正文：熟悉的会话列表、消息与输入框，配合工具活动、代码 Diff 和权限确认。用适合手机的方式，接着处理远端正在运行的 Claude 与 Codex 会话。

场景一：**继续交代任务** — 阅读上下文，补充要求，查看 Agent 的回复与执行进展。

场景二：**检查改动与测试结果** — 阅读项目文件和 Diff，查看 Agent 返回的测试输出，再决定下一步。

场景三：**处理等待中的操作** — 回应支持的授权请求与问题，需要时停止当前任务。

按钮：**Cmux Remote iOS 安装指南**

### 画面建议

单独展示足够大的 iPhone 会话细节，重点是一段完整工作流：发出补充要求 → Agent 修改和测试 → 查看 Diff → 确认下一步。不要使用迷你终端或满屏命令输出作为手机主画面。

Codex 仅用于说明交互参照，不使用官方品牌背书。桌面 Agent TUI 的范围与手机结构化会话的支持范围分别描述。

## 07 · 开始使用：按两端角色写安装步骤

### 页面文案

标题：**把远端设备，接到你的开发日常。**

步骤一：**准备远端 Mac** — 安装 cmux 与 Cmux Remote Companion，完成首次连接设置，运行你的 Agent，并开启需要共享的工作区。

步骤二：**选择接入设备** — 在 Mac 上使用 cmux ssh 或 Companion 工作区镜像；在 iPhone 上添加远端主机，完成配对。

步骤三：**确认权限，开始开发** — Companion 首次接入由主机确认设备与工作区权限；需要从外网用 iPhone 连接时，再配置自建中转。

主按钮：**下载 Cmux Remote Mac**

次按钮：**Cmux Remote iOS 安装指南**

辅助链接：**Mac 连接指南** · **Relay Server 部署指南**

### 画面建议

三步保持简短。SSH 的身份验证沿用 cmux 自己的流程，不把 Companion 配对审批描述为 SSH 的必经步骤。平台支持与安装细节放安装指南，首页不暗示已经提供 Linux / Windows Companion。

## 08 · FAQ：解决会影响选择的问题

### Cmux Remote 和 cmux 是什么关系？

Cmux Remote 是独立开源项目，非 cmux 官方产品。Companion 使用公开接口与 cmux 协作，无需修改或替换官方应用。

### 已经有 cmux ssh，为什么还需要 Companion？

cmux ssh 提供原生 SSH 工作方式。Companion 增加远端工作区镜像，以及 iPhone 的会话、项目改动和受支持操作入口。你可以按场景选择使用。

### Agent 和代码到底运行在哪里？

继续运行并保存在远端设备上。Mac 和 iPhone 接入远端已有的开发环境；Cmux Remote 不另建一套模型服务或 Agent 运行环境。

### iOS 客户端支持哪些 Agent？

当前结构化会话围绕远端已在运行、且能准确识别的 Claude 与 Codex 会话。可以发送补充要求、阅读历史和项目改动、停止任务，以及回应支持的权限请求。其他 Agent TUI 的桌面操作与手机会话支持是不同范围。

### 一定要部署 Relay Server 吗？

不一定。局域网或已有 VPN / Tailscale 网络能访问主机时，可以使用直连。iPhone 无法直接访问主机时，再配置自己的中转。自动发现是否可用取决于网络配置，也可以通过地址添加。

### 中转服务由谁提供？

由使用者自行部署和管理。仓库提供 Cloudflare Workers 与 Durable Objects 的部署方式；本项目不提供托管中转服务。
