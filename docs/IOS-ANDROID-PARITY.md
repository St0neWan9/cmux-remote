配对、双栏、连接详情、诊断日志、Feed 全事件、添加 Mac 覆盖层与返回、图片分享 chooser、长按菜单、选文页、时间页。
两台隔离 Bridge 同时登记后，列表出现两个 Mac 标签、4 条待处理，且同 id 的两条会话不再触发 LazyColumn
重复 key（会话选择改为 `hostID + session.id`，与设计文档一致）。附近设备发现只在模拟器上验证了“无结果时正常显示”，
真实局域网 / 企业 Wi-Fi 仍需真机回归。

**真实环境（2026-10-31 晚）**：隔离 Bridge 连本机真实 cmux-tui daemon，走 `enrollment open` → Android 登记 →
`enrollment approve --control`（只授权一个临时 workspace，含 `conversationStart`）。在模拟器上：

- 通过 App“新建会话”让 Bridge 启动真实 Claude 终端并发出第一条消息，真实 Agent 回复；
- 另起一个真实长对话：60 次 + 90 次独立 Bash 工具调用，转录 156 条消息；
- 列表、分组（60 / 90 个操作）、工具卡输出与退出码、回合用时、模型名均正确；
- 首次读取 100 条，上翻补页后 SQLite 缓存增长到 156 条且无重复；Bridge 重启导致 generation 变化时按设计整段替换；
- 停掉 Bridge、杀进程再启动：列表用缓存显示该 Mac 的会话，打开长对话从 SQLite 恢复全部 156 条，离线状态条正常；
- 测试中发现并修复：某个 Mac 失败时它自己的缓存会话列表会从列表消失、generation 变化后不回到最新、顶部补页只触发一次。

真实环境中 workspace 标题在离线时只能显示 UUID（快照只存了会话，未存 workspace 名称），记为后续小改进。
测试用的 daemon workspace、Agent 终端已关闭。

第三轮后仍存在的差距：

- 会话与任务缓存目前由前台的读取/翻页/打开任务写入，后台同步仍只预取会话列表与待处理数量。
- relay 目录（跨 relay 列出 Mac）与 relay origin 管理未做。
- 深链、通知 / FCM、TTS、触感按计划明确不做或待定。
- 真机折叠姿态、真机 Keystore backing、DeX / 多窗口、TalkBack 全量走查仍需设备验收。

## 16. 结论

- **核心链路完整**：配对、列表、历史、发送、停止、Feed 回答、图片、项目、新建会话、恢复、重命名、模型切换、后台任务、链路订阅、relay、重连。
- **与 iOS 的主要差距**：搜索/排序/工作区过滤/抽屉、Markdown 与表格渲染、活动分组与工具卡展开、滚动锚定细节、语音输入、Feed 的多模式决定与多问题表单、连接详情与诊断、多 Mac、后台刷新、本地化（无英文资源）。
- **Android 的独有价值**：折叠屏/大屏自适应布局，以及链路与中转的统一选路。
- 对照时 iOS 侧的两个已知问题（非 Android 引入）：`terminalRead/terminalInput` 能力有标签但无终端界面；后台刷新文案写“最多 3 个”，代码实际 4 个。
