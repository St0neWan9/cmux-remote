# iOS 设计系统

Cmux Remote 使用全白画布和悬浮控件，沿用已确定的 Codex 手机端视觉方向。本规范与 Mac 的原生窗口规范独立；页面使用共同组件，避免各自定义颜色、间距和按钮。

## 设计令牌

| 项目 | 规范 | 实现 |
| --- | --- | --- |
| 画布 | 整页纯白，包括状态栏和安全区域 | `WhitePage`；会话保留独立的透明头部 |
| 内容区域 | 两侧各 20 pt；所有卡片在这个区域内占满宽度 | `MobileDesign.pageInset`、`FloatingSurface` |
| 间距 | 分组 24 pt、行内 12 pt、卡片内 16 pt | `MobileDesign` |
| 卡片 | 白色、22 pt 圆角、轻描边和柔和阴影 | `FloatingSurface` |
| 工具展开卡片 | 极浅灰内容底；正文始终左对齐、长行换行 | `ToolDetailCard`、`ToolCodeBlock` |
| 文字 | 系统动态字体；标题 headline、正文 body/callout、元数据 caption | 不缩小文字来掩盖溢出 |
| 主操作 | 蓝底白字胶囊 | `FloatingButtonStyle(prominent: true)` |
| 次操作 | 白底黑字胶囊、轻阴影 | `FloatingButtonStyle()` |
| 危险操作 | 白底红字，保留 destructive 语义 | 同一按钮样式读取 Button role |
| 禁用 | 中性文字、降低不透明度，同时禁用交互 | 同一按钮样式读取 isEnabled |
| 图标按钮 | 44 × 44 pt 白色圆形触控区域 | `FloatingIconStyle` |
| 输入 | 白底、16 pt 圆角、统一内边距和描边 | `FloatingInput` |
| 操作组 | 能放下时横排，否则纵排，不截断按钮标题 | `ActionRow` |

卡片在添加内边距、背景之前先撑满可用宽度；不能用卡片内文字长度决定外框宽度。页面先确定内容列，再加一次页面边距。长设备名、地址、路径、身份指纹允许换行；身份内容保留选择复制。

## 导航和手势

- 每个入口由 `AppNavigationStack` 创建一个原生 NavigationStack，内部详情页复用这个栈，不再各自嵌套栈。
- 会话、连接详情、项目文件/差异、待处理事项、工具完整内容、历史图片、运行时间、扫码页都使用 push。头部返回、屏幕左边缘拖动和 VoiceOver escape 回到同一个上级页面。
- 入口和每个详情页显示时，`InteractivePopInstaller` 仅替换本栈 interactivePopGestureRecognizer 的 delegate，以及 iOS 26 的 interactiveContentPopGestureRecognizer delegate。使用 UIKit 原生交互转场，不用覆盖整页的 DragGesture 假装返回；根页和转场中不能再开始 pop。移除对应页面时恢复原 delegate；已由另一个可见页面接管时不覆盖它。
- 主页的左边缘打开抽屉；进入详情后关闭抽屉手势，避免争抢返回。抽屉仍支持滑动关闭。手势位移和展开状态在同一事务中提交，松手不先归零再展开；背景和阴影覆盖完整屏幕，正文保留安全区域。
- 系统照片选择器、文件选择器、授权确认保留系统交互。详情页不使用伪装成返回按钮的模态关闭。
- 原有读请求、图片加载、语音和轮询的离开页面取消规则保留；取消返回手势时页面继续展示。

## 页面清单

| 页面 | 共同规则 / 特殊内容 |
| --- | --- |
| 配对 | 扫码是唯一突出主操作；附近设备、等待批准、高级设置使用满宽分组；高级输入不套系统灰色 Form |
| 扫码 | 白色悬浮返回头部；摄像头内容在安全区域内；缺少相机时显示现有本地化说明 |
| 会话列表 | 白底，统一内容列、搜索输入和导航图标；项目与会话保持清晰缩进 |
| 抽屉 | 同样的字体、页面边距、操作按钮；保留主页移开的抽屉效果 |
| 会话 | 保留用户气泡、agent 正文、运行时间、结束按钮、白色透明虚化头部和浮动输入栏 |
| 连接详情 | 设备名、状态、满宽身份与权限卡片；值在标签下左对齐；刷新和断开按钮满宽 |
| 项目 | 同样的路径输入和操作组；文件正文与差异等宽字体、可选文本，改动行保留行级触控 |
| 待处理事项 | 满宽内容卡片；选择态明确；答复、拒绝、更多模式及反馈输入复用共同组件 |
| 工具完整内容 | 同栈返回；字段切换、可滚动左对齐正文、能换行的分页操作组 |
| 图片 | 同栈白色头部、适应内容的图片、统一复制/分享操作；保留加载、失败和重试状态 |
| 运行时间 | 同栈白色头部；保留来源说明和无记录状态，不把估算时间标记为精确记录 |

## 验收边界

iOS 构建、模型测试、本地化检查与模拟器实际交互分别记录。检查中文/英文、长文本、动态大字体、空状态、请求失败、滚动、连续 push/pop 和抽屉返回。真机摄像头、触控及 TestFlight 安装仍需单独验收；模拟器通过不能替代这些结果。

原生组件测试：`scripts/test-ios-navigation.sh <本任务已启动的 Simulator UDID>`。脚本禁用并行设备克隆，只使用显式指定的现有设备。测试实际挂载 NavigationStack，连续三次 SwiftUI push/pop，并检查隐藏头部后原生手势仍启用、根页禁止 pop、移除时恢复 delegate；在 320/430 pt 宽度与普通/辅助功能大字体下检查短、长卡片占满同一个留白列。

触控验收可传 `--fixture <隔离后端的 phone.json>`，UI 测试实际滑回连接详情、会话、项目、待处理事项、运行时间、历史图片和工具完整内容的上级，并保存页面截图。测试脚本在结束/失败时恢复 Simulator 原配对文件。未提供测试后端时明确跳过触控测试，只运行组件测试；不能把跳过计作手势验收。隔离后端使用 `scripts/build-phone-ui-fixture.py` 和 `.build/phone-ui-fixture <私有状态目录> <空闲端口>`，不会向真实 cmux 发送操作。

Apple 的 [内容区返回手势文档](https://developer.apple.com/documentation/uikit/uinavigationcontroller/interactivecontentpopgesturerecognizer) 说明了新手势与边缘返回的分工；旧系统只使用边缘返回。布局和请求状态更新会重新应用隐藏头部设置，因此在可见页面的原生布局生命周期中维护手势，避免只在首次出现时启用。

本轮验收覆盖 201 个 Swift 包测试、90 项手机模型检查、7 项发布配置检查；英文/简体中文键集一致。原生组件测试覆盖连续导航和两种屏宽/两种字体级别，触控测试从 7 个页面实际滑回，并留存截图。扫码和图片草稿预览使用相同导航组件；相机、语音、真机触控及断网连接仍不以本次布局验收替代。
